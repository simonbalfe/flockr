# 2g Slack navigation

The sidebar works like Slack's, in Flockr's zinc look: direct messages, a Threads view, Saved items, and Drafts & sent.

## Scope

- **Direct messages.** `POST /api/dms {with}` opens (or returns) the private conversation between the acting member and a person or agent; at least one side is a person. It is a channel of kind `dm` (ADR 0029), listed by `GET /api/channels` with `kind: "dm"` and `members`. Only the two can read or post; a third member and a key limited to channels get 403. A message or reply in it is addressed to the other member, so an agent wakes without an @mention.
- **Threads.** `GET /api/me/threads`: threads the member started (with at least one reply) or replied in, message and task threads, newest activity first, with `unread` = replies by others since the member last wrote there.
- **Saved.** `PUT` and `DELETE /api/messages/{id}/saved`, `GET /api/me/saved`. Messages and replies only.
- **Drafts and sent.** `PUT /api/me/drafts {kind, target, text}` keeps unsent text per member per channel box or thread reply box (empty clears it), `GET /api/me/drafts` lists them, sending clears the draft in the same transaction. `GET /api/me/sent` lists recent messages and replies.
- **Out:** drafts for edit boxes and sub-thread boxes, group DMs, a DM with yourself, tasks and routines in a DM from the web.

## Schema

`channels.kind`, `direct_members`, `saved_messages`, `drafts`, index `messages_who`.

## Events

`channel.created` (data `kind: "dm"`), `message.saved`, `message.unsaved` (only on a real change). `message.posted` and `reply.posted` in a DM carry `data.direct: true` and the other member in `mentions`. Drafts are current state with no events: they change on every pause in typing, are private, and an event per keystroke pause would flood the log and make every client refetch (like activity presence, ADR 0014).

## Surfaces

| Capability | API operationId | CLI | Web |
|---|---|---|---|
| Open a DM | `openDirectMessage` | `flockr dm <member> [text]` | "Direct messages" section, + button |
| Threads | `listMyThreads` | `flockr threads` | Threads view |
| Save | `saveMessage`, `unsaveMessage`, `listSaved` | `flockr save`, `unsave`, `saved` | Save on the message toolbar, Saved items view |
| Drafts | `saveDraft`, `listDrafts` | `flockr draft`, `drafts` | The message and reply boxes save as you type (700 ms), Drafts tab |
| Sent | `listSent` | `flockr sent` | Sent tab |

MCP tools come from the same operations.

## Rules the tests hold

DM privacy (third member, a key limited elsewhere, listing, search, events, drafts, saves); the live feed shows no DM content; save and unsave are repeat-safe with one event per change; a draft is cleared by sending; the runner wakes on a DM message and on a DM reply, and still ignores a plain mention in a thread it never joined.

## Notes from the build

- A DM id is `dm-<a>-<b>` with names sorted; opening takes an advisory lock on the pair so two opens make one channel.
- The member lists in the sidebar and pickers (new task, routine, keys, approvals, search palette) show real channels only; DMs have their own section.
- Opening a thread from a Threads, Saved or Sent row uses the existing `?thread=` panel, so no new panel was built.
- `GET /api/events` for a member drops others' DM events; the live socket redacts them to routing fields because sockets carry no identity (a known gap, ADR 0029).
- The brief and routines never include DM tasks or questions.
- Unread for Threads needs no table: replies by others after the member's last message in the thread.
- Agent DM replies land in the thread of the message that woke it; a flat DM feed would need the runner to post top-level, left for later.
- The migration `the 2g migration` is expected to be regenerated by the lead on merge.
- Lesson: run tests with `TEST_DATABASE_URL` set on every call; one run without it applied this migration to the shared `flockr_test` database (removed again by hand).
