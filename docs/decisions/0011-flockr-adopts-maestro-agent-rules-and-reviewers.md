# 0011: Flockr adopts maestro-service's agent rules and reviewers

Status: accepted, 24 Nov 2026.

## Problem

Agents are building Flockr with no project rules of their own: no always-loaded instructions, no code conventions, no review method and no design rules for the web app. maestro-service already has all of these, tuned over many sessions, but much of it is about its own business (clients, ad spend, Slack, Cloudflare).

## Options

| Option | Good | Cost |
|---|---|---|
| Write Flockr's rules from scratch | Fits exactly | Slow; relearns lessons maestro-service already paid for |
| Copy maestro-service's rules as they are | Fastest | Rules about tenants, money and Cloudflare that mean nothing here and confuse agents |
| Port every agnostic part and adapt it, drop the business-only parts | Keeps the lessons, fits Flockr | Two rule sets to keep in step by hand when one learns something general |

## Choice

Port every agnostic part and adapt it. The same mechanism as maestro-service: rules in `.rulesync/rules/overview.md` and skills in `.rulesync/skills/`, generated by rulesync into `AGENTS.md`, `CLAUDE.md` and each harness's skills folder, with the generated files gitignored. The `review` skill keeps independent reviewers per kind (backend, typescript, security, frontend, docs, ux, design, observability), each proving its findings and writing a review file, run only when Simon asks. `bun run check` is the one gate, run by a pre-push hook. Lint rules are listed in `docs/guides/GUIDE_CODE_STANDARDS.md` and built later.

## Why

The rules that hold without maestro-service's business (no comments, Zod once at the edge, one definition per concept, fixed sets as one list, no provider branching, headless parity, docs with the change, ADR discipline, pinned dependencies) are exactly the ones Flockr's own ADRs already point at (0003, 0009, 0010). Reusing the same layout means an agent that knows one repo knows the other.

## Costs

- Rules are written ahead of the code they govern: most lint lines are planned, not enforced, until the lint setup is built.
- A general lesson learned in one repo has to be copied to the other by hand.
- Generated files are gitignored, so a fresh checkout must run `bunx rulesync@26.0.0 generate` before an agent sees the rules.
- Dropped for now: maestro-service's ban on subagents, its master-agent loop and its phase workflow skill; each can be ported later if Flockr needs it.
